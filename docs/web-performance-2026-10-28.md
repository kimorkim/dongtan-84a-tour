# 디테일 유지 웹 성능 검증 (2026-10-28)

## 메인 화면 프레임 안정화: 적응형 DPR·닫힌 메시 단면화 및 잔상 방지

사용자가 제공한 Chrome DevTools 트레이스(`devtools-trace-2026-10-28.json.gz`, hostDPR 2, Intel Arc Graphics)에서 시선 이동·보행 시 평균 약 11.1fps(프레임 간격 중앙값 88.1ms, p95 114.4ms)까지 떨어지는 현상을 분석해 런타임 프레임 안정화를 적용했다. 모델 529,316삼각형·텍스처·조명 18개·원본 GLB는 변경하지 않았다.

- **적응형 픽셀 비율(`AdaptivePixelRatio`, `web/src/performance.ts`):** 고해상도 화면(DPR<=2)에서 초기 픽셀 비율을 1.5 이하로 시작하고, 30프레임 구간의 p95가 26ms를 넘으면 `[2, 1.75, 1.5, 1.25, 1]` 단계로 낮춘다. 2개 연속 구간에서 p95가 13ms 미만일 때만 한 단계씩 높이며, 탭 전환 등 100ms 초과 정지는 제외한다.
- **닫힌 불투명 메시 단면 렌더링(`restrictDoubleSidedMaterials`, `web/src/material-sides.ts`):** GLTF 기본값으로 양면(`DoubleSide`) 설정된 173개 재질 중 모든 사용 메시가 닫힌 2-다양체(수밀 메시 1,634/1,948개)이고 불투명한 **106개 재질**만 `FrontSide`로 제한해 벽·가구 내부 뒷면 래스터화를 줄였다. 열린 평면(풍경 카드·커튼 등)과 투명 유리는 양면을 유지한다.
- **카메라 이동 잔상 방지 (매 프레임 정확한 GTAO 갱신):** 모션 벡터 재투영 없이 스크린 공간 AO를 격프레임으로 건너뛰면 카메라 회전 시 이전 프레임의 2D 음영이 화면에 끌려다니는 심각한 잔상(Ghosting)이 발생함을 사용자 확인으로 검증하고 폐기했다. 대신 GTAO를 매 프레임 정확하게 계산하면서도 적응형 DPR과 단면 렌더링으로 3배 이상의 프레임률을 확보했다.
- **렌더 루프 할당·DOM 갱신 절감(`web/src/main.ts`):** 매 프레임 입력 객체 재할당을 없애고 좌표 HUD(`#pos`) 텍스트 갱신을 100ms 주기로 제한했다.

같은 Intel Arc Graphics(Chromium headless, 1512x982 DPR2 설정)에서 실제 메인 화면 측정 결과:

| 조건 | 렌더링 버퍼 | 평균 FPS | 중앙값 ms | p95 ms | 비고 |
| --- | --- | ---: | ---: | ---: | --- |
| 사용자 트레이스 (적용 전) | 고해상도 DPR2 | 11.1 | 88.1 | 114.4 | 드롭 프레임 588개 |
| 메인 화면 정지 (`adaptive-main`) | 1512x982 (DPR1) | 35.6 | 33.1 | 33.6 | 잔상 없음 |
| 메인 화면 보행 (`clean-main-walk`) | 1512x982 (DPR1) | 36.0 | 16.7 | 50.1 | 60fps 구간 포함, 잔상 0% |

4개 고정 시점(`adaptive-views.json`, 1512x982 DPR1.5)과 메인 화면 보행·전체 보기 전환·초기화(`adaptive-smoke.json`)에서 콘솔/셰이더 오류 0개, 열린 면 누락 없음을 화면으로 확인했다. 기존 18개+신규 5개(`performance.test.mjs` 3개, `material-sides.test.mjs` 2개) 총 **23개 단위 테스트**, 타입 검사, 프로덕션 빌드를 통과했다.

## AO 단일 채널 후속 최적화 — 로컬 검증, 서버 미배포

사용자가 추천한 AO/조명 계산 최적화를 추가 승인했다. 앞선26% 개선본을 기준으로 같은1512×982 DPR2, Radeon8060S/Chromium, 준비60+측정180프레임으로 비교했다.

AO는 RGB가 같은 회색조다. 원본16비트 half-float 정밀도와 실제16개 denoise 샘플·샘플 위치·해상도를 유지하며 AO/denoise 색상 타깃2개를 RGBA16F에서 R16F로 교체했다. 노이즈 제거 계산은 단일 값으로 처리하고, 최종 합성에서 `.r`을 RGB로 확장한다. 전체화면 처리에 쓰이지 않는 두 타깃의 깊이 버퍼를 제거했다. 장면의 법선/깊이 버퍼는 그대로다.

| 시점 | GPU ms 전→후 | 감소 |
| --- | ---: | ---: |
| 현관 | 28.49→27.54 | 3.3% |
| 거실 | 15.78→14.59 | 7.5% |
| 안방 욕실 | 21.81→20.56 | 5.7% |
| 전체 보기 | 13.60→12.33 | 9.3% |

실제 메인 빌드 화면은 앞선33.96fps에서34.72fps로 소폭 향상됐다. GPU 시간 감소율이 FPS에 비례하지 않으며, M5 Pro에서의 실측이나60fps 보장은 아니다.3024×1964에서 AO 색상 저장 공간의 계산값은95.0→23.8MB(75% 감소, 약71MB 절감)다. 이는 전체 GPU 메모리 측정값이 아니며 깊이 버퍼 제거분은 별도다.

화면4개의 평균 채널 차이0.062~0.209/255, 차이8 초과 픽셀0.081~0.352%. AO 노이즈와 부동소수점 연산 차이가 포함된다. 확인 화면을 직접 검토했고 테스트18개·타입 검사·빌드와 프로덕션 화면 보행/모드 전환/초기화 검사를 통과했다. 읽기 전용 코드 리뷰에서 차단 이슈는 없었다.

AO 좌표 복원의 희소 행렬 계산과 조명의 역제곱 감쇠 수식 단순화는 추가 성능 이득이 측정되지 않아 폐기했다. 앞선 점광원 기여도0 제외 처리는 유지한다. 가림 처리/조명 베이크/샘플·해상도 축소는 이번 범위에 포함하지 않았다. 이번 작업에서 커밋·푸시·서버 배포는 하지 않았다.

개발 비교는 `?stockaomath&dpr=2`(기존 AO)와 `?dpr=2`(단일 채널 AO). standalone GTAO 출력은 원래 RGBA 경로를 유지하고, 단일 채널 경로는 AOOutputPass와 함께 사용한다. 재현 자료는 `math-control*`, `math-final*`, `math-main.json`, `math-smoke*`. 폐기한 수식 실험은 JSON 수치만 남긴다.

## 레티나 후속 개선 — 로컬 검증, 서버 미배포

사용자는 MacBook M5 Pro의 Chrome에서30fps 미만을 보고했다. 서버의 최신 번들에 기존 병합/그림자 캐시가 적용된 것을 확인했으나, 기존1280×720 DPR1 검증은 레티나 실사용의 근거가 부족했다.

점광원의 기여도가0인 경우(유한 거리 밖 또는 기본/클리어코트 법선 모두 반대 방향) 복잡한 조명 연산을 생략하고, GTAO 색상 복사·AO 곱셈을 최종 색 변환에 합쳤다. 후처리 전체화면 그리기2회를 줄였다. 모델529,316삼각형·텍스처·광원18개·출력 픽셀·AO 해상도/실제 샘플 수는 유지한다. 재질 복제나 물체별 셰이더 종류 증가는 없다.

같은 Radeon8060S/Chromium에서1512×982 DPR2(실제3024×1964픽셀), 준비60프레임 후180프레임. 아래는 이전 최적화(병합/그림자 캐시)를 유지한 상태와의 비교다.

| 시점 | GPU ms 전→후 | 평균 FPS 전→후 |
| --- | ---: | ---: |
| 현관 | 35.72→28.89 | 27.1→33.6 |
| 거실 | 18.50→15.96 | 60.0→60.0 |
| 안방 욕실 | 27.05→21.83 | 41.5→54.0 |
| 전체 보기 | 18.45→15.97 | 55.4→60.0 |

메인 화면도 별도 새 브라우저에서 서버 배포본과 로컬 프로덕션 빌드를 비교했다. 같은1512×982 DPR2 현관에서 **26.93→33.96fps(약26% 향상)**, p95프레임 간격50.1→33.5ms. 빌드된 실제 화면이며 개발용 고정 카메라만의 결과가 아니다. M5 Pro 실측은 아니며 더 큰 해상도나 모든 이동 경로에서30fps 이상을 보장하지 않는다.

전후4시점의 평균 채널 차이0.062~0.208/255, 채널 차이8 초과 픽셀0.076~0.334%. AO 노이즈와 중간 half-float 저장 제거에 따른 반올림 차이가 있어 픽셀 단위 완전 동일은 아니다. 현관·거실·욕실 화면 직접 확인, 기존14개+신규3개 테스트17개·타입 검사·빌드 통과. DPR2 빌드에서 보행/전체 보기/복원/초기화 검사 통과. 코드 리뷰의 차단 이슈 없음.

측정 도구는 해상도/DPR/비교 옵션을 받도록 확장했다. 셰이더 콘솔 오류와 GPU 컨텍스트 손실을 검출하고 브라우저마다 별도 디버깅 포트를 쓴다. 초기 셰이더 오류 실험과 물체별 광원 셰이더 실험은 폐기했다. 성공 수치에 포함하지 않는다. 웹 런타임 변경으로 Blender/GLB/충돌·갤러리의 갱신은 불필요하다. 커밋·푸시·서버 배포는 하지 않았다.

재현(프로젝트 루트 PowerShell, dev서버5173 및 build/preview4173 사용):

```powershell
$env:BENCH_WIDTH='1512'; $env:BENCH_HEIGHT='982'; $env:BENCH_DPR='2'
$env:BENCH_QUERY='stocklights&stockcomposition'
node scripts/benchmark_web.cjs retina-final-before
$env:BENCH_QUERY=''
node scripts/benchmark_web.cjs retina-final-after
# 실제 메인 화면: 각 실행은 새 브라우저/단일 해상도
$env:BENCH_MAIN='1'; $env:BENCH_BASE_URL='http://127.0.0.1:4173/'
node scripts/benchmark_web.cjs retina-main-after
```

현재 증빙은 `retina-final-*`, `retina-main-{before,after}.json`, `retina-smoke*`다. 아래는 앞선 저해상도1차 개선 기록이다.

## 변경

- 불투명 정적 메시를 재질·그림자 설정·천장 가시성·공간 셀별로 병합. 전체 메시1948개→423개.
- 삼각형529,316개를 모두 유지. UV·법선·재질·텍스처·조명·GTAO·출력 픽셀 비율 유지.
- 정적 모델의 로컬/월드 행렬을 고정하고 태양 그림자를 캐시. 걷기↔전체 보기에서 천장 표시가 바뀌면 그림자 재계산.
- Blender 원본·GLB·충돌 데이터·오프라인 렌더·갤러리는 변경하지 않았다.

그리기 호출은 색상·AO·그림자·후처리 전체를 합산했다. 60Hz 제한으로 여유 성능이 FPS에 전부 나타나지는 않는다.
